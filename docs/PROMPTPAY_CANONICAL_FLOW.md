# PromptPay Canonical Flow

## หลักการ

PromptPay เป็นช่องทางอ้างอิงการรับและจ่ายเงิน ไม่ใช่ชื่อธนาคารและไม่ใช่ข้อมูลบุคคลหลัก รูปสลิปและ OCR เป็นหลักฐานต้นฉบับที่ห้ามเขียนทับ ส่วนข้อมูลใช้งานจริงอยู่ใน Canonical projection เพียงชุดเดียว

## Flow

`สลิปต้นฉบับ → Intake/AI → บัญชีตรวจสองฝั่ง → Payment Alias → Canonical Party → จัดสรรเงิน → Module ปลายทาง → ปิดรายการ`

1. สลิปหนึ่งใบสร้างธุรกรรมหลักหนึ่งรายการ
2. บันทึกฝั่ง `sender` และ `recipient` แยกกัน
3. แต่ละฝั่งเลือก `บัญชีธนาคาร`, `PromptPay` หรือ `ยังไม่ทราบ`
4. PromptPay เก็บเฉพาะชนิด, ค่าแสดงแบบปกปิด และ Fingerprint ที่ salt ด้วย Company ID
5. ชื่อ Canonical ตรงพนักงาน, Vendor, ลูกค้า หรือบริษัทเพียงหนึ่งรายการจึงเชื่อมอัตโนมัติ
6. ถ้ามีเพียงเลขท้าย, ไม่พบเจ้าของ หรือพบมากกว่าหนึ่งรายการ ให้ค้าง `needs_review`
7. การจัดสรรเงินและ Money Hop แยกจากช่องทางรับจ่าย ยอดรวมต้องตรงกับยอดสลิป
8. ทุกการยืนยันเพิ่ม Audit และ Document Flow Event ใหม่ ไม่แก้หรือลบหลักฐานเดิม

## สถานะ

- `evidence_only`: รู้ว่าเป็น PromptPay แต่ยังไม่ยืนยันเจ้าของ
- `needs_review`: ข้อมูลไม่พอสำหรับผูก Canonical
- `matched`: พบเจ้าของ Canonical หรือบัญชีธนาคารที่ตรงตามกติกา
- `conflict`: Alias เดิมขัดแย้งกับเจ้าของใหม่ ห้าม Auto Link

## ความเป็นส่วนตัว

- ไม่เก็บเลข PromptPay เต็มในตารางหรือ Audit
- UI แสดงเฉพาะเลขท้ายสี่ตัว
- Fingerprint ไม่สามารถใช้แทนเลข PromptPay ในการโอนเงิน
- RPC ยืนยันจำกัดเฉพาะ Admin/Manager/Accounting ที่มีสิทธิ์ในบริษัท
