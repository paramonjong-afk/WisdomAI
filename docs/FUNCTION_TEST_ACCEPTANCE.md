# Function Test Acceptance Standard

ใช้เกณฑ์นี้ทุกครั้งที่แก้ฟังก์ชัน Attendance, เวลาทำงาน, ค่าแรง, Payroll Preview, Reports หรือ Export และห้ามปิดงานจากเพียง lint, build, HTTP 200 หรือการพบ marker ใน bundle

## เกณฑ์บังคับ

1. ทดสอบผลลัพธ์ระดับรายการด้วยเวลาเข้า–ออกจริง ไม่ทดสอบเฉพาะว่า Function ถูกเรียกได้
2. แยกและแสดงให้ตรวจสอบได้ระหว่างหลักฐานเวลา, ผลตรวจของระบบ และผลจ่ายหลัง Admin ปรับ
3. ครึ่งวันเช้าต้องเทียบขอบเขตช่วงเช้า และครึ่งวันบ่ายต้องเทียบขอบเขตช่วงบ่าย
4. เวลาเข้า–ออกที่ครอบคลุมทั้งช่วงเช้าและบ่ายแต่ผลคิดเป็นครึ่งวันต้องเป็น `รอตรวจ` ห้ามเดาช่วงเวลา
5. Grace period ต้องใช้กฎเดียวกันทุกวัน ทุกหน้า และทุกช่องทาง
6. หลังแก้เวลา ต้องคำนวณจากหลักฐานล่าสุดและหักเวลาที่ไม่นับ ห้ามใช้ยอดสะสมเก่า
7. ค่าในหน้าเว็บ, CSV และ PDF ต้องมาจากผลคำนวณชุดเดียวกันและตรงกัน
8. ทดสอบสิทธิ์และ tenant isolation รวมถึง Audit ผู้แก้ เวลา ค่าเดิม ค่าใหม่ และเหตุผล
9. หลัง Deploy ต้องทำ authenticated data smoke/UAT อย่างน้อยหนึ่งรายการที่ตรวจค่าคาดหวังได้; HTTP 200 เป็นเพียง deployment smoke ไม่ใช่ business acceptance

## ชุดข้อมูลอ้างอิงขั้นต่ำ

| กรณี | กะ/ช่วงที่ใช้ตรวจ | เวลาเข้า–ออก | ผลที่ต้องได้ |
| --- | --- | --- | --- |
| ครึ่งวันเช้า | 08:00–12:00 | 07:37–12:07 | สาย 0, ออกก่อน 0, ออกเกิน 7 นาที |
| ครึ่งวันบ่าย | 13:00–17:00, ผ่อนผัน 5 นาที | 14:00–18:00 | สาย 55, ออกก่อน 0, ออกเกิน 60 นาที |
| ครึ่งวันกำกวม | กะเต็ม 08:00–17:00 | 08:43–17:01 | รอตรวจและให้ Admin เลือกช่วง/ผลจ่าย |
| Grace period | กะเริ่ม 08:00 | 08:05 และ 08:06 | ใช้เกณฑ์ผ่อนผันเดียวกันและแสดงผลตาม Config |
| แก้เวลา | แก้ clock in/out เดิม | ก่อนและหลังแก้ | worked minutes และผลคิดวันเปลี่ยนตามหลักฐานล่าสุด |

## คำสั่งตรวจมาตรฐาน

```text
npm run test:function:payroll-attendance
npm run lint
npm run build
```

การปิดงานต้องบันทึก expected/actual ของชุดข้อมูลจริงหลัง Deploy พร้อมยืนยัน Web/CSV/PDF ตรงกัน หากยังไม่มี authenticated data verification ให้สถานะเป็น `review` หรือ `doing` เท่านั้น
